# Test Quality Standard

写测试或生成测试计划时，测试必须证明行为正确，而不是证明实现“被调用过”或“文件存在”。

- **行为优先**：断言用户可见行为、公开 API、命令输出、持久化结果、错误类型或状态变化；避免只断言 mock 调用次数、函数类型、对象非空。
- **断言要窄**：关键输出优先用 `toBe` / `toEqual` / `toMatchObject` / 精确错误类型；`toContain` 只用于文本搜索，不能替代结构或行为验证。
- **必须覆盖失败路径**：新增/修复关键逻辑至少包含正常路径、边界输入、错误输入或权限/状态异常中的两类；Bug fix 必须有能先失败的复现测试。
- **测试数据要真实**：包含空值、额外空格、换行、Unicode、无效格式、重复项、缺字段等噪声；禁止只用刚好完美的数据。
- **集成测试要验内容**：生成文件、脚手架、渲染、命令执行类测试，必须验证关键内容/结构/差异；不能只检查路径存在或 JSON 可解析。
- **避免实现耦合**：测试公共契约和可观察结果，不锁死内部私有函数、临时变量名或实现顺序。
- **去重**：相同逻辑用 `test.each` 或共享 helper 合并；禁止复制一组只改名字的测试。
- **验收映射**：每个新增测试必须能映射到 `spec.md` 的 AC、`plan.json` 的 `tests` 条目，或本次 bug 的复现步骤。
