# Auto-Discovery 流程

1. 分析 [context]，提取关键实体（功能名、模块名、文件路径、类名、错误信息片段）。
2. 在 tasks/ 索引中按以下优先级匹配：
   - 精确匹配 Task 标题或 slug
   - 模糊匹配 Task 标题（编辑距离 / 关键词重合）
   - 通过 map.json directoryMapping 反查关联 Task
   - 通过 dictionary.json 实体注册反查关联 Task
3. 匹配结果分支：
   - 唯一匹配 → 自动锁定，输出“已自动定位至 <ID>_<Slug>”，进入子协议主流程。
   - 多个匹配（≤ 5）→ 列出候选（ID + 标题 + 一句话摘要），询问用户选择。
   - 多个匹配（> 5）→ 报错“匹配模糊，请提供 <ID> 或更具体的描述”，终止。
   - 无匹配 → 报错“未定位到相关 Task，请提供 <ID> 或检查描述准确性”，终止。

# 输出契约

- 自动锁定时须显式告知用户：“已自动定位至 FEAT-07_user-login，依据：context 中提到「登录按钮」与 task 标题精确匹配”。
- 用户可在子协议 step_2 之前回复“换一个”撤回选择，回到候选列表或重新提供描述。
