## 调用方式

- **自动调用**: 否，不由模型根据 description 自行触发。
- **触发位置**: 仅由 `/archi.*` 协议在对应步骤显式调用。
- **执行上下文**: 可在当前上下文内联执行；涉及用户提问时必须回到主对话。
- **边界**: 只辅助生成选项、访谈问题或结构化片段，不自行推进协议步骤。


# 补充访谈协议

## 核心原则

**选择题优先**。禁开放式提问（如「你想用什么数据库？」）。每题给 3-5 选项 + `[Z] 自定义`，AI 按上下文推荐一项，用户确认或换选即可。目标：用户不具备专业知识也能做合理决策。

## 规则

1. 仅问 `gaps` 中的缺口，禁自行扩展主题
2. Brief / `context` 中用户已表态的禁再问，直接采纳
3. 强相关缺口合并为一题，弱相关拆题
4. 每题 3-5 选项 + `[Z] 自定义 (请描述)` 兑底
5. 推荐项标 `[推荐]`，理由需结合 `context`，禁机械套默认
6. 选项「说明」须含：是什么 / 选了项目会怎样 / 适合什么场景（2-3 句，禁一词）
7. `AI+` / `AI-` 从 AI Agent 执行视角写完整句子；每方案必有取舍，禁写「无」
8. 问题数 ≤ `max_questions`

## 输出格式

```
### 补充确认

**[Q<n>] 问题标题**
> 一句话说明为什么需要这个信息

| ID | 选项 | 说明 | AI+ | AI- |
|:---|:---|:---|:---|:---|
| A [推荐] | 选项名 | 2-3 句说明 | 完整句子 | 完整句子 |
| B | ... | ... | ... | ... |
| Z | 自定义 | (请描述) | - | - |

（多题重复上述 Q-table）

**INPUT**: `Q1答案 | Q2答案 | ...`（题间用 `|`；单题多选用空格，如 `A B`）
```

## 反例速查

| 错误 | 违反规则 | 修法 |
|:---|:---|:---|
| `A | PostgreSQL` | #6 一词说明 | `A | PostgreSQL | 关系型数据库，Schema 固定后 AI 推导 CRUD 稳定，适合实体关系清晰的业务` |
| `AI+: 性能好` | #7 非完整句 | `AI+: 结构化 Schema 让 AI 从类型直接推导 CRUD，减少猜测` |
| `AI-: 无` | #7 禁逃避 | `AI-: 迁移脚本须随 Schema 演化同步维护，AI 容易遗漏字段变更` |
| 问 Brief 已表态的技术栈 | #2 | 跳过，直接采纳 |
