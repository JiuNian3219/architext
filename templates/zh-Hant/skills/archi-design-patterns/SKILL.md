# 技術方案結構化模式庫

## 系統流程定位

```
/archi.plan step_4_generate → design.md § 2
    ↓
[本 Skill] 模式選擇 → 格式生成 → 自檢
    ↓
design.md § 2 Core Mechanisms 內容
```

> **Skill 的職責邊界**：
> - 負責：模式選擇指南、各模式的標準表格格式、自檢清單
> - 不負責：design.md 的整體結構（見 `design.template.md`）、參數/不變量/故障模式（見範本 §§ 3-5）

---

## 模式選擇指南

根據機制特徵選取 ≥1 個模式。同一功能可組合多個（如連線管理用 State Machine + 訊息處理用 Pipeline）。

| 機制特徵 | 推薦模式 | 典型場景 |
|:---|:---|:---|
| 有離散狀態集合與狀態間轉移 | **State Machine** | 連線管理、工作流引擎、元件生命週期、認證流程 |
| 資料/請求經過有序處理步驟 | **Pipeline** | 訊息解碼鏈、中介軟體棧、資料轉換管道、請求攔截器 |
| 行為取決於多條件組合 | **Decision Matrix** | 權限判定、策略路由、降級規則、特性開關 |
| 兩個或多個元件間有定義好的訊息交換 | **Protocol** | 客戶端-服務端通訊、行程間 IPC、事件匯流排、Worker 訊息 |

**執行流程**: 選定模式 → 填寫對應標準格式 → **立即執行自檢** → 有未通過項須修補後重檢 → 全部通過再進入下一個機制。

## 模式 A: State Machine

### 標準格式

**States (狀態集)**:

| 狀態 | 含義 | 進入條件 |
|:---|:---|:---|
| `idle` | [初始/空閒] | [初始化完成 或 主動斷開] |
| `connecting` | [連線建立中] | [發起連線請求] |
| `connected` | [已連線] | [收到 open 事件] |
| ... | ... | ... |

**Transitions (轉移表)**:

| From | → To | Guard (觸發條件) | Action (副作用) |
|:---|:---|:---|:---|
| `idle` | `connecting` | [使用者觸發連線] | [建立 Socket 實例] |
| `connecting` | `connected` | [收到 open 事件] | [啟動心跳, 清空重試計數] |
| `connecting` | `disconnected` | [超時 或 error 事件] | [記錄錯誤, 遞增重試計數] |
| ... | ... | ... | ... |

### 自檢清單

| # | 檢查項 | 驗證方法 |
|:---|:---|:---|
| 1 | **完整性**: 無死鎖 | 每個狀態至少一條出邊 |
| 2 | **可達性**: 無孤島 | 每個非初始狀態至少一條入邊 |
| 3 | **終止性**: 有退出路徑 | 存在終態或穩態循環 |
| 4 | **確定性**: 無歧義轉移 | 同一狀態的出邊 Guard 互斥 |
| 5 | **異常覆蓋**: 非 Happy Path Only | 每個非終態都有 error/timeout 出邊 |

## 模式 B: Pipeline

### 標準格式

| Step | Input | Process | Output | On Error |
|:---|:---|:---|:---|:---|
| 1. [步驟名] | [輸入型別] | [處理邏輯] | [輸出型別] | [丟棄/重試/中止/降級] |
| 2. [步驟名] | [上一步 Output] | [處理邏輯] | [輸出型別] | [錯誤處理] |
| ... | ... | ... | ... | ... |

### 自檢清單

| # | 檢查項 | 驗證方法 |
|:---|:---|:---|
| 1 | **型別鏈**: 無斷裂 | Step N Output = Step N+1 Input |
| 2 | **錯誤處理**: 無靜默吞錯 | 每步都有 On Error |
| 3 | **冪等標註**: 重試安全性明確 | 標註哪些步驟可安全重試、哪些有副作用 |
| 4 | **可恢復性**: 可安全終止 | 任意 Step 錯誤後可恢復或安全退出 |

## 模式 C: Decision Matrix

### 標準格式

| 條件 A | 條件 B | 條件 C | → 行為 | 備註 |
|:---|:---|:---|:---|:---|
| [值1] | [值1] | [值1] | [行為] | |
| [值1] | [值1] | [值2] | [行為] | |
| [值1] | [值2] | * | [行為] | *=任意值 |
| * | * | * | [兜底行為] | 未匹配時預設處理 |

### 自檢清單

| # | 檢查項 | 驗證方法 |
|:---|:---|:---|
| 1 | **窮舉性**: 無遺漏 | 所有條件值組合已覆蓋（* 通配未列舉組合） |
| 2 | **無歧義**: 單一命中 | 同一輸入只命中一行（行間優先級從上到下，或條件互斥） |
| 3 | **兜底行**: 有預設處理 | 最後一行為 * 通配 |
| 4 | **可測試**: 可構造用例 | 每行可構造測試輸入驗證 |

## 模式 D: Protocol

### 標準格式

**參與方**: [Component A] ↔ [Component B]

| Seq | Sender → Receiver | Message | Payload | Expected Response | Timeout |
|:---|:---|:---|:---|:---|:---|
| 1 | [A → B] | `[訊息名]` | {[欄位: 型別]} | `[響應名]` {[欄位: 型別]} | [Ns → 超時處理] |
| 2 | [B → A] | `[訊息名]` | {[欄位: 型別]} | 無 (單向推送) | - |
| ... | ... | ... | ... | ... | ... |

### 自檢清單

| # | 檢查項 | 驗證方法 |
|:---|:---|:---|
| 1 | **配對性**: 有去有回 | 需要響應的訊息都定義了 Response + Timeout |
| 2 | **型別明確**: 無 any | 每個 Payload 欄位有具體型別 |
| 3 | **順序依賴**: 前置聲明 | 標註哪些訊息必須在哪些之後 |
| 4 | **並發安全**: 有策略 | 多訊息並發時說明處理策略（佇列/丟棄/合併） |
